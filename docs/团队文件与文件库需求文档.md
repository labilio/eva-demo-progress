# 团队文件与文件库需求文档

> 状态：原型改造方案（V1）  
> 权限基线：[文件库角色与权限矩阵](./file-library-permissions/index.html)

## 1. 目标

完善【项目 → 团队文件】和一级入口【文件库】，让用户能够上传、查找、预览和整理文件，并在两个入口间看到一致的数据与权限结果。

核心原则：**同一套文件数据、同一套权限判断、两个不同范围的视图。**

## 2. 产品定位

| 功能 | 定位 | 默认范围 |
| --- | --- | --- |
| 团队文件 | 当前项目的文件空间 | 当前项目内的文件与文件夹 |
| 文件库 | 用户可访问文件的统一入口 | 个人空间、已加入的项目空间，以及仍有权读取的会话文件 |

- 团队文件不是独立网盘，不单独维护成员和角色。
- 文件库不复制项目文件；项目文件在两个入口中使用同一个文件 ID。
- 会话文件保留来源权限，只作为聚合结果展示，不因此获得项目文件权限。

## 3. 本期范围

### 3.1 两个入口共同具备

- 浏览文件夹、面包屑导航、搜索、类型筛选。
- 预览、下载、查看详情、复制文件内部链接。
- 上传本地文件、新建文件夹。
- 在当前空间内重命名、移动、复制。
- 上传进度、成功、失败重试、同名冲突、无权限和空状态。
- 按 Owner、Manager、Editor 控制按钮是否出现及操作是否成功。

### 3.2 团队文件

- 默认进入当前项目根目录，不再选择空间。
- 项目成员均可浏览、预览、下载、上传和整理文件。
- 项目群成员均可将群文件保存到本项目；保存后生成项目副本，不扩大来源群权限。
- 文件详情显示：所属项目、所在目录、来源、创建者、最后修改者、大小和时间。
- Owner、Manager 可进入回收站；Editor 不显示删除、回收站和治理入口。

### 3.3 文件库

- 左侧按“个人空间／项目空间／会话文件”组织，不把所有来源混成一个可随意整理的目录。
- “所有文件”用于跨来源搜索与筛选；进入具体空间后才能执行整理操作。
- 从文件库上传时，先选择个人空间或有权限的项目空间。
- 项目文件可跳转到对应项目的团队文件，并定位同一个文件。
- 会话文件只提供来源允许的查看、预览、下载和内部链接，不显示文件空间治理操作。

## 4. 权限与归属

- 仅使用 Owner、Manager、Editor；不设置 Viewer 或单文件只读角色。
- 文件没有独立 Owner。项目负责人是项目文件空间 Owner，项目管理员映射为 Manager，普通项目成员映射为 Editor。
- 会话文件不是新的文件空间；是否可读沿用来源会话权限，界面不把“可下载”包装成 Viewer 角色。
- 上传者、群文件保存者、专家、专家团或数字员工只记录为“创建者／来源”，不会成为文件 Owner。
- 任务产出写入任务所属项目空间；任务负责人是谁不改变文件空间归属。
- 项目成员退出后，立即失去该项目文件访问权。
- Editor 不允许删除文件、查看回收站或从回收站恢复。
- 不做项目之间、个人与项目之间的移动或复制。

## 5. 本期不做

- 在线文档创建或协同编辑。
- 文件版本管理。
- 文件级独立权限、Viewer、外部公开分享。
- 跨空间移动或复制。
- “添加文件快捷入口”。

## 6. 当前原型的主要问题

1. 团队文件、文件库和群文件转存分别维护数据，两个入口不能稳定展示同一个文件。
2. 文件库仍显示“文件所有者”“可下载”等旧概念，与已确认权限规则冲突。
3. 文件库的“分享”和“添加快捷入口”语义未定义；应改为“复制内部链接”，并删除快捷入口。
4. 文件库上传没有先选择目标空间，项目团队文件的上传也没有复用同一上传状态。
5. 项目团队文件的菜单没有完整接入 Owner／Manager／Editor 权限。
6. 回收站、空间信息、空间链接、设置和审计尚无完整入口或状态。

## 7. 修改计划

### P0：统一基础能力

- 建立唯一 `FileStore`，统一普通上传、项目群保存和任务产出。
- 文件对象统一为：`id`、`spaceId`、`parentId`、`name`、`type`、`size`、`source`、`createdBy`、`updatedBy`、`status`、`deletedAt`。
- 建立唯一权限函数，所有菜单、详情和操作提交均调用同一判断。
- 删除全局文件库中的独立资源数组和“共享文件”旁路数据。

### P1：完善项目团队文件

- 统一工具栏、列表、文件夹导航和详情抽屉。
- 接通上传、新建、预览、下载、重命名、移动、复制。
- 接通项目群文件保存，并展示来源群／子区／任务信息。
- 按角色隐藏删除、回收站和治理入口。

### P2：完善文件库

- 按个人空间、项目空间、会话文件重做左侧导航。
- 增加全局搜索、来源筛选和目标空间选择。
- 项目文件支持跳转并定位到团队文件；两个入口共享选中和详情规则。
- 移除“文件所有者”“我的权限”“快捷入口”；补充所属空间、来源和创建者字段。

### P3：补齐治理能力

- Owner、Manager：回收站、恢复、永久删除、空间链接、空间设置、审计。
- Owner：设置／取消 Manager、转移项目所有权。
- 成员管理直接跳转项目设置，不在文件库维护第二套成员列表。

### P4：验证与收口

- 覆盖 Owner、Manager、Editor 三种身份及项目退出后的权限变化。
- 覆盖本地上传、项目群保存、任务产出、删除恢复和入口往返。
- 验证 1440px、1024px、720px、键盘操作、200% 缩放及错误状态。
- 删除旧 DOM 页面、重复 CSS、重复监听器和无调用方代码。

## 8. 核心验收标准

1. 同一项目文件在团队文件与文件库中 ID、名称、目录和修改时间一致。
2. 用户无权访问某项目时，两个入口都不返回该项目文件。
3. Editor 可上传和整理，也可查看空间成员，但看不到删除、回收站、成员管理、链接管理、设置和审计操作。
4. 项目群所有成员都能保存群文件；保存项目副本后仍不能读取无权访问的群历史。
5. 专家或专家团产出的文件归项目空间，详情只把执行者记为创建者。
6. 文件库上传必须选择目标空间，且不能选择无权限空间。
7. 不出现 Viewer、单文件 Owner、在线文档、文件版本或跨空间操作入口。
