# 我的 AI 团队：子区承载会话

2026-09-07，用户明确批准实施。本文件取代 Step 1 中团队侧独立 OpenClaw session 的方案，个人 Eva 不在调整范围。

## 产品合同

- 中栏保留云端分身、数字员工分组、默认折叠与现行三栏尺寸。身份继续使用公共 Eva Logo＋主人头像、跟随姓名的 AI 标。
- 每个 AI 身份对应“当前本人＋该 AI”的专用两人群；每段对话对应这个群下的一个子区。该群作为会话容器，不提供父群公共聊天入口，不进入普通项目群列表。
- 对用户统一称“会话／对话”。不显示子区图标、群人数、父群／子区面包屑、成员邀请、退出群、群治理或子区归档等操作。
- 右侧标题只显示 AI 头像、姓名及 AI 标；会话名及重命名只在中栏提供。聊天信息直接复用普通私聊结构，只显示对象身份、免打扰、置顶及清空记录。
- 新建立即分配默认名称“新对话”，重名递增编号，可直接讲话。首次发送后取首条消息前 20 个字符作为名称；如果用户此前手动改名则保持自定义名称。改名接受 1–50 个字符，拒绝纯空白。
- 会话操作菜单提供重命名、置顶／取消置顶和删除。保留删除无需确认、删除当前项后选择同身份剩余会话、没有剩余时进入新对话的行为。置顶只在当前身份内排序。
- 本人直接发送就触发当前 AI；这是固定且唯一的方式，不能设置成必须 @。此规则仅适用于这种两人会话，普通项目群和子区仍按已有 @ 规则执行。
- 切换对话保持消息和草稿隔离；打开聊天信息或改名不重建消息流及输入区。仍只有一个客户端系统标题栏。

## 原型实现与状态归属

`009-3-ai-team-store.js` 提供共用的 `EvaAIPrivateConversations` 适配器：以稳定本人 ID 与 AI ID 推导唯一两人群，声明两名成员及 `direct-only` 回复策略；不复制人员或项目。`009-3-digital-employees-store.js` 使用同一个群／子区适配器。

子区使用 Octo 字段 `group_no`、`short_id`、`channel_id`、`channel_type: 5`，完整频道 ID 为 `group_no + "____" + short_id`。现有持久化集合名 `sessions`、旧记录 ID 及兼容 API 保留，含义已改为子区记录，不代表 OpenClaw session，也不同时维护第二份消息集合。读取及新建补齐群／子区关系，不替换已有标题、消息、草稿或置顶数据。

页面 React 组件唯一拥有当前身份／会话选择与弹窗状态。选择通过 `source.selectedThreadId` 传给既有 ChannelsView，走原有 `fa` 子区选择、`threadMessages` 消息读取与共享输入框。`presentation: ai-direct` 仅控制标题、头像、输入提示与聊天信息的私聊外观；底层 `chatType` 保持 group。

会话标题／置顶仍由各自业务 store 唯一维护。聊天信息复用 `EvaChatSettings`，通过配置回调执行改名和置顶，不再保存第二份置顶状态；免打扰和清空记录复用公共聊天偏好，按完整子区频道 ID 隔离。

本仓库仍是本地存储驱动的原型，AI 回复仍为既有模拟回执。本次未创建真实 Octo 服务端群、未连接真实 AI，不能把前端子区频道隔离表述为已验收的模型上下文隔离。后续服务联调需要按同一群／子区 ID 映射落地，并保证两人成员范围与固定免 @ 策略。
