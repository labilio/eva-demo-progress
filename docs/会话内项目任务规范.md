# 会话内项目任务规范

本规范适用于团队 IM 中的任务入口、后续消息转任务入口及其创建流程。依据本轮已确认的产品定义：**这里的任务只指所属项目的 Loop 任务**。它不是个人待办、自动化任务，也不是某次 AI session 的执行记录。

## 1. 入口与适用范围

| 会话类型 | 项目任务入口 | 任务归属 |
| --- | --- | --- |
| 项目全员群 | 有权限时显示 | 当前项目 |
| 项目内普通群 | 有权限时显示 | 群所属项目 |
| 项目群的子区 | 有权限时显示 | 子区所在群的项目 |
| 非项目群及其子区 | 不显示 | 无 |
| 人与人私聊 | 不显示 | 无，即使双方同属项目 |
| 人与分身、数字员工的私聊 | 不显示 | 无，即使该 AI 加入了项目 |
| 我的 AI 团队的 OpenClaw session | 不显示 | 无 |
| 个人 Eva 会话 | 不显示此入口 | 不适用 |

不得根据名称、聊天内容提到的项目、上一次打开的项目或 AI 的归属猜测任务项目。子区先解析父群，再通过成员体系的稳定 ID 获取项目。当前供应链演示关联：协作项目 `prod`，任务看板项目 `p-supply`；二者是适配关系，不得复制项目。

## 2. 当前交互与后续边界

当前实现：会话右上角“创建任务” → 在当前会话上打开统一 Loop 创建弹窗 → 确认提交 → 关闭弹窗并显示完整任务编号。不得跳转项目页替代创建入口。

所属项目由当前群/子区解析并传入表单，不依赖上一次打开的项目。提交时再次校验群及项目权限。创建后保留当前会话；任务进入所属项目看板。当前没有自动发送聊天任务卡片，不能把提示成功说成已发送任务卡片。

后续若加入“将消息转为任务”，必须继续复用同一创建组件和数据入口；消息只能预填上下文，必须让用户检查并提交。不能把 AI 的建议、普通消息发送或打开任务页视作创建授权。

## 3. 权限与数据边界

- 展示与点击时均检查：当前人类账号能够访问父群和所属项目。无权限时不显示入口；权限发生变化后不得继续进入或提交。
- 项目成员可以创建任务，不把创建权限擅自收紧为管理员专属。UI 操作身份来自当前账号，不把私聊对象当作创建者。
- 创建时重新检查项目存在及访问权限。当前项目固定，不在来自会话的创建流程中切换其他项目。
- 执行负责人只能来自当前项目可用的人类、分身、数字员工或项目专员；身份名称与类型从稳定 ID 对应的业务数据派生，不能接受表单伪造值。
- 验收人只能是当前项目的人类成员。父任务必须属于同一项目；任务详情、评论、子任务和执行历史必须按任务及项目隔离。
- 数字员工能参与项目任务不等于能被拉进群；不能借创建任务绕过成员或身份规则。

## 4. 创建表单

| 字段 | 规则 |
| --- | --- |
| 所属项目 | 固定显示当前项目 |
| 标题、任务目标、完成标准 | 必填，去除首尾空白后不可为空 |
| 执行负责人 | 必选，候选范围见权限规则 |
| 补充上下文 | 可选，可说明背景、约束与参考资料 |
| 优先级 | 默认中，可调整 |
| 截止日期、验收人 | 可选，保存到任务并在描述中展示验收安排 |
| 创建人、创建时间 | 只读系统字段；创建人取当前人类账号，创建时间在任务实际提交时自动记录 |
| 附件 | 可选，当前原型单文件上限 20 MB |
| 标签 | 有可选标签时显示，无标签时不放空选择器 |
| 初始状态 | 待办 |

选中项及候选身份复用公共头像组件；AI 标紧跟姓名。沿用现有 Semi 表单和弹窗规范，系统标题栏保持可见，标题与底部操作固定，长内容内部滚动。

## 5. 提交、编号与后续状态

- 只有显式点击“创建任务”才提交；提交期间防止重复点击创建多份任务。失败保留填写内容，允许重试；已创建后补存标签失败，不得再次创建任务。
- 编号保留项目前缀，例如 `SC-108`。在当前项目中递增，并支持完整编号查找。不能仅展示数字或为新任务改写旧任务编号。
- 成功后关闭表单，任务进入所属项目待办列；会话入口保持当前会话，项目看板入口刷新看板；取消不创建任务。
- 给 AI 分派任务不等于启动执行。不得自动展示“执行中”、历史运行或成功结果；新任务没有执行记录时应显示真实空状态。
- 目标、标准、上下文和验收安排允许使用 Markdown；日常短文字不强行增加标题或表格。

## 6. 状态归属与实现位置

- 项目、群、子区与成员权限：`prototype/009-2-membership.js`。
- 会话任务入口及项目路由：`prototype/009-5-patch-im.js`，统一 IM 内核的配置，禁止各入口复制任务控件。
- 任务创建、查询和数据隔离适配：`prototype/009-6-patch-general.js`。
- 统一创建表单及样式：`prototype/049-loop-task-create.js`、`prototype/049-loop-task-create.css`。
- 表单草稿由组件持有，在关闭后重新打开、项目或父任务切换时重置；异步结果必须校验当前表单代次，不污染新表单。

当前为本地原型：任务和附件保留在当前页面内，附件使用本地对象 URL，并未上传服务端。真实 CLI 查询、后端持久化、调度执行和聊天任务卡片回流未完成，不能以预设内容冒充实际联调结果。

## 7. 验收要求

获得测试授权后，覆盖入口矩阵、项目切换、权限变化、身份候选、重复提交、失败重试、完整编号查询和新任务空历史。至少走通“项目群 → 右上角创建任务 → 弹窗提交 → 留在原会话 → 到所属项目核对任务”；返回后不得串会话、重复输入区或覆盖系统标题栏。私聊和非项目群必须没有该入口。

本规范记录规则及当前实现范围，不表示本次已重新执行验收。
