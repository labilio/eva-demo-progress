# 我的 AI 团队：Step 1 实施规格

日期：2026-09-06。设计依据为同目录两份客户材料及《我的AI团队-Step1设计基线》。本文件将 PM 后续确认落实为可编码的原型合同；不证明真实 OpenClaw、Octo 或客户系统已接通。

## 本次目标

在团队原“我的 AI”入口中，按助理、分身、数字员工组织本人可使用的 AI。保留个人 Eva 同学入口，保留系统标题栏、路由出口和 Octo 消息内核。暂用名称“我的 AI 团队”已获 PM 认可，客户正式命名仍未定。

## 已确定的流程

| 类别 | 来源与入口 | Step 1 行为 |
| --- | --- | --- |
| 助理 | 本地个人助理，经 Octo 接入供本人使用 | “连接助理”选择已存在的本地助理；同一来源只连接一次。此次不在团队内创建本地助理。 |
| 分身 | 从本地助理自动生成的云端代表 | “创建分身”选择来源，自动导入配置；来源不必先连接团队。允许同一来源生成多个分身，自动命名并加序号。 |
| 数字员工 | 客户已有系统 | 保留分类及“未接入”说明；不虚构员工、能力清单、运行记录、市场或创建流程。 |

左侧按角色分组，组内列身份及其团队会话；右侧复用 ChannelsView 的消息流和输入区。身份与会话是不同对象，不用 Octo 群代替本地助理身份，不把数字员工硬造为聊天对象。

选中身份可以新建对话、查看详情。新建先进入草稿态，首次发送非空文本才生成会话，标题取首条消息前 20 个字符；同一身份的会话按更新时间排序。草稿按身份或已有会话隔离，切换页面后不串入其他会话。个人会话历史不导入团队。

创建或连接时显示处理中，防止重复点击；失败时保留选择并给出可重试状态，不出现半成品身份。没有候选助理时说明需要先到个人 Eva 同学创建。分身无需填写业务域、项目或群：PM 已明确，加入具体项目或群时由用户选择带入哪个分身，本步不设计加入流程。

## 配置与同步

PM 最新决定：本步默认配置全自动，不提供云端或团队侧编辑，不设计双向同步和冲突策略。详情只读显示来源、角色、运行位置、配置和同步状态。个人侧现有创建/改名使用同一份本地助理数据，关联助理显示同步更新；分身配置自动跟随来源版本，分身名称保持稳定。

原型使用模拟适配器和浏览器本地存储，不读取本机文件、真实记忆或私有工作记录，不进行网络上传。演示配置同步不等于材料全文共享；依据文档中关于授权、共享记忆和正式成果发布的规则仍适用于后续真实实现。

本地助理离线时不可发送。分身自身仍可接待，配置同步等待本地恢复；旧请求不得覆盖较新来源版本。同步错误可重试，详情展示已同步版本与状态。刷新时恢复数据，存储损坏或不可用时给出说明，不静默声称保存成功。

AI 回复由模拟适配器返回克制的确认收件文案，不执行真实任务。按 PM 最新要求，产品页面按正式界面呈现，不写“原型演示”、研发备注或解释性批注；技术边界记录于本文与交付说明。分身负责接待、转交、跟进和回传，不生成专业结论、不作业务承诺；正式成果和业务责任仍归人。

## 工程归属

| 对象 | 唯一所有者／数据源 | 重置边界 |
| --- | --- | --- |
| 导航模式与选中态 | URL `/messages?evaIM=my-ai` | 路由变化 |
| 本地助理、接入身份、配置、会话及草稿 | `EvaAITeam` 数据服务，只读不可变快照 | 浏览器本地存储恢复；无第二份个人助理列表 |
| 选中身份、选中会话、弹窗和处理中状态 | React 页面组件 | 离开模式后组件卸载；草稿仍由数据服务保存 |
| 消息呈现、操作及输入 | 既有 `ChannelsView` 统一内核 | 身份／会话变化时重置内核内部状态 |
| 数字员工 | 无已接入数据 | 本步仅呈现占位状态 |

数据模块放在 `009-3` 分层，IM 适配与组件在 `009-5` 构建补丁，导航名与图标在 `009-7`，页面 CSS 放独立样式文件。新增加载项同时登记 `index.html` 与 `prototype-manifest.json`。补丁精确锚点失败即停止构建。

PM 已明确：这是首个按新 GDS 实现的模块，其他页面此前没有依据该规范开发。视觉以仓库 GDS 2.0 的语义 token、组件合同与参考状态为准；允许与旧模块暂时存在风格差异，不为追求旧页面一致而削弱规范，也不顺带改造其他页面。团队会话仍采用 Octo，不能把个人 260/940 骨架强加到团队 IM。新增常规控件复用 Semi UI，图标复用 Lucide。弹层限制在客户端内容区，系统标题栏始终可见。

## 验证与发布

数据验证覆盖重复连接、多分身命名、草稿隔离、首次发送、离线、同步竞态与存储恢复；集成验证覆盖个人来源改名、创建与详情、路由切换及共用 IM。

运行仓库测试、构建、manifest、项目、路由、侧栏、补丁 hash 和生成模块语法检查。通过 Edge 实测“目标入口 → 其他入口 → 返回”，核对选择、消息、输入区、弹窗、刷新恢复和标题栏；静态检查不代替浏览器验收。

遵守 `CONTRIBUTING.md`：当前在 `codex/my-ai-team` 开发，功能分支通过 PR 与 Preview 交付。用户当前任务明确确认合并上线后，才合入最新 main、执行 `npm run release:bump`、重新验证、合并 PR，并核对 Vercel Production 目标 commit 与页面版本。开发期不修改 `release.json`，不默认手动部署。

在线批注由另一台电脑维护，本步不修改 `review/` 或 `supabase/`。

本地验证（2026-09-06）：40 项自动测试通过；构建、manifest、项目、协作、消息路由、侧栏、补丁 hash、生成模块语法、GDS 与 diff 检查通过。Edge 实测 1200×800 和 1440×900，连接助理、创建分身与重名编号、只读配置、首次发送、跨身份草稿恢复、数字员工空态、消息入口往返、刷新保留和个人改名触发分身版本同步通过。Esc 关闭配置后焦点回到查看配置按钮；标题栏保持可见。离线、失败及同步竞态为数据层测试证据，未伪称真实设备联调。

交付为功能分支 PR / Preview，尚未获准合并 main 或更新正式版本。页面中不放实施或验收批注。
