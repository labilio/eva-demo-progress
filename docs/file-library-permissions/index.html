E 文件库权限设计 角色与动作矩阵

FILE SPACE PERMISSION

三个角色，一张权限矩阵

文件库不维护独立成员，项目角色自动映射为文件空间角色。项目成员最低即 Editor，不设置 Viewer 或单文件只读角色。

01

角色

O

Owner

个人空间本人，或项目负责人。唯一角色，负责文件空间最终治理。

M

Manager

项目管理员。可管理全部文件内容、回收站和操作记录，但不能单独改变项目归属。

E

Editor

普通项目成员。可查看、上传和管理项目文件，但不能永久删除或查看完整操作记录。

任务负责人不是文件 Owner

专家、专家团和数字员工不属于上述角色。执行任务时仅临时读取已选输入、写入当前任务产出；产出归项目文件空间，业务责任仍落到项目内人类。

补充：把原先只有“上传新版本”的定义补齐为查看、上传和恢复版本，并补上同空间复制。

合并：发现空间、查看空间、浏览、搜索和元数据读取，统一为“浏览、搜索、查看详情”。

不纳入：查看自身权限、权限来源、Owner 同步属于系统能力；任务输入、任务产出确认属于任务模块；快捷方式和独立空间设置当前没有明确产品入口，暂不设计；排序、筛选和收藏不改变共享权限，无需放入角色矩阵。

统一规则：文件本身不设置独立 Owner；上传者或 AI 生成者只用于来源和审计；项目成员退出后立即失去项目文件访问权。
